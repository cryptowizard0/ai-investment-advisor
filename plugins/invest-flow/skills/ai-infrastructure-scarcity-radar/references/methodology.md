# AI 基建稀缺机会雷达方法论

## 核心原则

所有结论必须建立在以下证据链上：

`AI 架构变化 -> 用量变化 -> 供给约束 -> 公司财务 -> 市场预期`

若任一关键环节缺失，必须降低优先级或标记为“待验证”。如果一个机会只有需求增长，没有单位用量弹性、供给约束或财务兑现，不得判定为稀缺机会，只能归类为普通景气或概念主题。

## 1. AI 架构变化分类

优先寻找能改变单位用量、系统 BOM 或部署瓶颈的变化：

| 架构变化 | 典型影响 | 重点验证 |
|----------|----------|----------|
| 单机训练到 rack-scale / cluster-scale | GPU 间互联、交换、供电、散热、机柜集成需求上升 | 每 rack GPU 数、网络端口数、功耗密度 |
| Training 到 inference 扩散 | 推理集群规模、存储读取、网络流量和边缘部署变化 | token volume、推理成本、部署区域 |
| Dense model 到 MoE / 多专家模型 | 通信、路由、内存带宽和存储访问模式变化 | expert routing、all-to-all 通信、HBM 容量 |
| 多模态 / 长上下文 | HBM、SSD、对象存储、网络和内存容量需求上升 | context length、KV cache、存储吞吐 |
| GPU 到 custom ASIC / AI ASIC | 封装、HBM、板卡、软件栈和供应链重新分配 | 大客户自研芯片量产节奏 |
| Copper 到 optical / CPO | 高速光模块、硅光、激光器、光纤连接器需求变化 | 速率升级、功耗预算、交换架构 |
| 风冷到液冷 | CDU、冷板、快接头、泵阀、冷却液和运维需求增加 | rack power density、PUE、客户认证 |
| 高密度供电 | 变压器、UPS、PDU、储能、配电和电网接入瓶颈 | 数据中心 MW 增量、交付周期 |
| 存储层级变化 | SSD/HDD/NAND/近线存储需求结构变化 | 训练数据、推理日志、检查点和向量库 |

## 2. 八类产业链覆盖

| 类别 | 细分环节 | 常见瓶颈 |
|------|----------|----------|
| GPU / AI ASIC / 系统 | GPU、ASIC、整机、rack-scale 集成 | 先进制程、HBM、封装、系统验证 |
| 内存与存储 | HBM、DDR、NAND、SSD、HDD | 产能切换、良率、客户认证、价格周期 |
| 先进封装 | CoWoS、SoIC、ABF、substrate、测试 | 设备交期、良率、洁净室、关键材料 |
| 光互联 | 光模块、光芯片、激光器、硅光、CPO、光纤、连接器 | 速率迭代、可靠性、客户认证、良率 |
| 网络芯片 | Switch ASIC、NIC、DPU、Retimer、SerDes | 高速 SerDes、软件生态、客户绑定 |
| 电力 | 变压器、UPS、PDU、储能、配电 | 交付周期、产能、铜/硅钢片、认证 |
| 液冷 | CDU、冷板、快接头、泵阀、冷却液 | 客户认证、可靠性、运维标准、供应链 |
| 材料设备测试 | 半导体材料、设备、测试设备 | 技术门槛、交期、客户导入、出口管制 |

## 3. 供需缺口判断

### 需求侧
检查需求是否来自真实架构变化，而不是单纯叙事扩散：
- 单位用量是否上升：每 GPU、每 rack、每 MW、每 token、每 model training run。
- 是否非线性增长：速率升级、功耗密度、内存容量、端口数、封装面积、散热需求是否超过算力线性增速。
- 是否由头部客户 capex、产品路线图、订单、交付周期或管理层指引支撑。
- 是否存在从单一客户扩散到多客户的迹象。

### 供给侧
判断供给为什么扩不快：
- 扩产周期：厂房、设备、洁净室、良率爬坡、工程人才。
- 认证壁垒：云厂商、芯片厂、OEM/ODM、数据中心客户的验证周期。
- 关键设备或材料受限：先进设备、substrate、激光器、泵阀、铜材、硅钢片等。
- 客户绑定：design-in、qualification、长期供货协议、定制化规格。
- 资本纪律：行业是否经历过过剩周期，厂商是否谨慎扩产。

### 分类标准
- 真短缺：需求非线性增长 + 供给扩张慢 + 财务开始兑现 + 客户认证/技术壁垒明确。
- 高景气：需求强，但供给可较快扩张或竞争者多。
- 纯概念：只有 AI 叙事，缺少单位用量、供给约束和财务证据。

## 4. 公司真实受益验证

公司筛选必须落到可验证指标：
- AI 相关收入占比和增速。
- backlog / bookings / order visibility。
- ASP、毛利率、产品 mix、利用率是否改善。
- 新产能投放节奏和 capex。
- 客户集中度、design win、长期协议、认证状态。
- 存货、应收账款、预收款是否支持订单真实性。
- 管理层指引是否明确提到 AI 需求及其持续性。
- 分析师 revenue / EPS estimate revision 是否上修。

区分：
- 收入弹性：单位出货、ASP、AI 收入占比、订单可见度。
- 利润弹性：毛利率、良率、固定成本摊薄、产品 mix、议价权。

## 5. 市场定价检查

判断“市场是否已经充分定价”时至少检查：
- 估值分位：P/E、EV/EBITDA、P/S、PEG、FCF yield 与历史和同业比较。
- 股价反应：近 1/3/6/12 个月涨跌幅，相对指数和同业表现。
- 预期变化：收入、EPS、毛利率和 capex consensus 是否已大幅上修。
- 叙事拥挤度：是否成为卖方一致推荐、社交媒体热点或高频会议主题。
- 财务兑现差距：估值扩张是否早于订单和利润兑现。

若市场已经充分定价，但供需缺口仍在扩大，应归类为“值得跟踪但需等待更好风险回报”；不得因为逻辑正确直接提高优先级。

## 6. 风险框架

必须覆盖：
- 扩产过剩：产能在需求放缓后集中释放。
- 价格风险：ASP 下行、客户重新议价、产品标准化。
- 技术替代：铜互联替代光、ASIC 替代 GPU、风冷效率提升、封装路线变化等。
- 客户集中：单一云厂商或芯片厂砍单。
- 资本开支周期：hyperscaler capex 放缓或预算转向。
- 地缘与监管：出口管制、供应链迁移、补贴政策变化。
- 执行风险：良率、可靠性、交付、认证失败。

## 7. 评分口径

| 维度 | 高分含义 |
|------|----------|
| 需求确定性 | 需求来自明确架构变化，并有订单、capex 或客户路线图支撑 |
| 单位用量弹性 | 每 GPU、每 rack、每 MW 或每 token 用量非线性上升 |
| 供给约束 | 扩产周期长、良率难、认证慢、关键材料设备受限 |
| 技术壁垒 | 需要专利、工艺、可靠性、软件生态或系统级能力 |
| 客户绑定 | 已进入头部客户供应链，替换成本高 |
| 财务兑现 | 收入、订单、毛利率、指引或预期上修已经体现 |
| 预期差 | 市场尚未充分理解持续性、利润弹性或受益公司 |
| 周期风险 | 负分；扩产、价格、库存和替代风险越大越低 |

证据置信度：
- 高：公司文件、财报、交易所公告、客户披露、可验证行业数据一致。
- 中：有公司口径和第三方数据，但缺少直接量化。
- 低：主要依赖传闻、二手报道或逻辑推演。
