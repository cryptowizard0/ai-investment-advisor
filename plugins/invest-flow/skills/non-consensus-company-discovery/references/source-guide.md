# 非共识公司发现数据源指南

## 原则

- 优先使用可追溯的一手来源。
- 所有关键数字必须带日期和来源。
- 无法确认的数据标记为 `数据暂缺` 或 `不确定`。
- 同一核心假设尽量用公司自身、产业链上下游和第三方数据交叉验证。

## 来源优先级

| 优先级 | 来源 | 适用问题 |
|---:|---|---|
| 1 | 10-K、10-Q、20-F、S-1、年报、交易所公告 | 收入结构、风险、客户、财务、capex、债务 |
| 1 | Investor Relations、earnings call transcript、investor day | 管理层资源配置、订单、毛利率驱动、长期需求 |
| 2 | 上游供应商、下游客户、竞争对手、设备商电话会 | 产业链交叉验证、供需、价格、扩产周期 |
| 2 | 官方客户案例、产品文档、认证公告、合作公告 | 客户验证、商业化、迁移成本 |
| 2 | 招聘页面、LinkedIn、职位描述 | 新技术方向、销售/交付扩张、地区布局 |
| 3 | 专利、论文、技术白皮书、标准组织资料 | 技术路线连续性、壁垒、可替代性 |
| 3 | GitHub、开发者社区、API 文档、插件生态 | 软件、AI、云服务和工具链生态信号 |
| 3 | 权威行业研究、政府数据、监管文件 | TAM、政策、行业供需、监管变化 |
| 4 | 可信媒体和专业新闻 | 事件确认、订单、竞争动态 |
| 4 | 社交媒体和论坛 | 只能做弱信号，不能单独支撑结论 |

## 信息源使用方式

### 财报和电话会

重点寻找管理层反复强调但市场未充分定价的内容：
- 新产品。
- 产能扩张。
- 客户验证。
- 订单能见度。
- 毛利率驱动因素。
- 资本开支变化。
- 供应链瓶颈。
- 长期需求变化。

不要只看 EPS。要看管理层对未来 1-3 年的资源配置。

### 产业链交叉验证

不要只看目标公司。还要看：
- 上游供应商怎么说。
- 下游客户怎么说。
- 竞争对手怎么说。
- 设备商怎么说。
- 渠道商怎么说。

多个产业链公司同时提到同一趋势时，可信度提高。若公司自身表述与上下游矛盾，降低证据置信度。

### 招聘信息

招聘是早期信号，但不是财务验证。重点看：
- 招哪些岗位。
- 招聘地点。
- 招聘人数。
- 是否新建团队。
- 是否招聘某个新技术方向。
- 是否招聘销售和交付岗位。

技术岗位增加偏研发信号；销售和交付岗位增加偏商业化信号。

### 专利、论文和技术文档

重点不是数量，而是：
- 技术路线是否连续。
- 是否围绕核心产品。
- 是否与客户需求相关。
- 是否能转化为成本、性能或效率优势。

### 客户评价和开发者生态

尤其适用于软件、AI、云服务和工具链公司。观察：
- GitHub star 增速。
- 开发者讨论质量。
- API 调用生态。
- 社区活跃度。
- 客户案例。
- 用户迁移成本。
- 插件生态。

开发者喜欢的工具可能从边缘工具变成基础设施，但必须继续验证收入、留存和毛利率。

## 强信号与弱信号

强信号：
- 收入增长重新加速。
- 毛利率连续改善。
- 新业务占比提升。
- 大客户开始放量。
- 订单积压增长。
- 公司扩大资本开支。
- 行业出现供给瓶颈。
- 竞争对手跟进同一方向。
- 管理层持续回购。
- 市场仍然按旧业务估值。

弱信号：
- 媒体报道很多。
- 管理层讲故事。
- 投资者大会热闹。
- 社交媒体讨论增加。
- 股价短期大涨。
- 分析师开始推荐。

真正有价值的是业务数据变好，但市场叙事还没完全改变。
