# chain-alpha-pipeline 编排方法论

## 1. 执行模式与能力探测

主 agent 跨步串行（Step 1 → 2 → 3 → 汇总），步内对可拆分的工作单元 fan-out。

开始时探测当前 agent 会话是否支持派发 subagent（并行子任务）：

- **Claude Code**：若平台支持 Task/subagent 派发，进入并行模式，Step 2 按环节、Step 3 按公司 fan-out。
- **Codex**：若当前会话暴露 subagent 派发工具（如 `spawn_agent` / `wait_agent` / `close_agent`），默认进入并行模式，Step 2 按环节、Step 3 按公司 fan-out。
- **工具不可用、探测失败或派发失败**：降级为串行模式，在当前会话内顺序处理每个环节/公司。

并行与串行两种模式的硬门槛、漏斗纪律、交接字段、报告格式完全一致；唯一区别是是否并行。降级是默认安全路径：任何探测失败、派发失败或派发不可用，都回到串行模式，保证 Codex 与 Claude Code 的报告可比。

## 2. fan-out 规则

| 步骤 | fan-out 维度 | 并行单元数 | 收口 |
|---|---|---|---|
| Step 1 | 不 fan-out（全景不可分） | 主 agent 自己做 | 产出 2-4 个错位环节 |
| Step 2 | 每个错位环节 1 个 subagent | N ≤ 4 | 主 agent 汇总候选池，按 30 分排序 |
| Step 3 | 每家入选公司 1 个 subagent | M ≤ 6 | 主 agent 汇总验证卡 |

- **Step 3 收口（top-K）**：Step 2 的可投主板候选可能很多，主 agent 跨市场按 30 分排序只取 **top-K（默认 6）** 进入 Step 3 fan-out，不对全部可投候选逐一验证。
- **批次上限**：单波并行默认 ≤6 个 subagent，超出分批顺序派发。
- **Codex 并行约束**：派发前必须确认当前会话暴露 subagent 派发工具；每个 `spawn_agent` 任务使用自包含 prompt；主 agent 用 `wait_agent` 收齐 final message 交接字段，完成后关闭或释放已完成 subagent。
- 派发模板见 `references/subagent-prompts.md`。

## 3. 漏斗纪律

fan-out 不放宽任何门槛。

| 阶段 | 上限 | 不足时 |
|---|---|---|
| Step 1 错位环节 | 2-4 个 | 0 个则终止流程，输出全景列表 + 观察池，说明缺什么证据 |
| Step 2 每环节候选 | ≤10 家 | 0 家则该环节标"格局分散，暂不可投"，列格局最好的公司作背景 |
| Step 3 深挖 | 2-3 家 | 无"通过"及以上档位时触发兜底规则：列出最强格局者，不给仓位 |

各步骤 skill 自身的硬门槛（错位双证据、利润增速 ≥20%、CR3>50%、毛利 25%、占比双轨、100 分四档等）由步骤 skill 强制，编排层不得放宽。

## 4. 步骤间交接数据

Step 1 -> Step 2，每个错位环节传递：环节名称、在全景列表中的位置、错位强度评分（含错位定价程度分，0-1 分须标注"定价拥挤"）、利润增速落点（增速区间、口径、可持续性证据）、错位预计收窄时点、需求/供给证据摘要、供给约束实证清单。

Step 2 -> 主 agent（每家候选）：公司名、Ticker、子环节、候选 30 分、占比初值与置信度、利润增速与置信度、CR3 证据等级、上市地与可投性（可投主板，注明市场如 A股/港股/日股/台股/美股；仅粉单；未上市）、待核实事项。

主 agent -> Step 3（每家入选公司）：上述候选字段 + 待核实事项，作为单公司 verification 的输入上下文。

Step 3 -> 汇总（每家公司）：档位、总分、利润增速结论、仓位上限、反证条件、跟踪指标。

主 agent 默认用 subagent final message 返回的交接字段汇总，不回读报告文件；仅在字段缺失或需核对时回读 report_path。

## 5. 失败与降级处理

- **Step 2 某环节 subagent 失败/返回空**：不整体中止；用成功环节继续，汇总报告"候选漏斗"标注该环节"未完成（subagent 失败）"，并入降级章节。
- **Step 3 某公司 subagent 失败/返回"验证未完成"**：该公司标"验证未完成"，不给档位/仓位，其余公司正常汇总。
- **能力探测失败、派发失败或并行不可用**：整体降级为串行模式，行为与产出格式与并行模式一致。
- **Step 1 全部环节只是"高景气，非错位"**：终止，不强行进入 Step 2；报告给出升级触发条件（出现什么实证再重跑）。
- **Step 1/2 利润增速低于 20%**：不放行到下一步；报告标注"利润弹性不足"，列出达到 20%/30% 所需触发条件。
- **Step 2 候选全为不可投（未上市/仅粉单）**：Step 3 跳过，报告说明可投资性受限，列出最强格局者作背景参考。
- **数据缺口（占比/CR3 拿不到）**：照常进入下一步但降低置信度标注，不得编造数字。

## 6. 会话成本控制

- 完整 pipeline 建议在单独会话运行，避免主会话上下文耗尽。
- 并行模式下，subagent 各自独立上下文，主会话只保留交接字段，显著降低主会话上下文压力。
- 三步必须顺序执行（后一步输入依赖前一步输出）；步内 fan-out 的多个 subagent 互不依赖，可并行。
