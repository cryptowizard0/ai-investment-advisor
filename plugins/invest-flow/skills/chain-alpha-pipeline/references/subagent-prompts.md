# chain-alpha-pipeline subagent 派发模板

本文件供主 agent 在并行模式下派发 Step 2 / Step 3 / Step 4 子任务使用。每个 subagent 是独立、无本会话记忆的执行单元：prompt 必须自包含，带齐输入上下文与交接字段要求。

## 通用约定

- 每个 subagent 只跑一个步骤 skill、只处理一个工作单元（单环节或单公司）。
- subagent 必须：(1) 读取对应步骤 skill 的 SKILL.md 与 references 后按其规则执行；(2) 把报告写到该 skill 的 output 目录；(3) 在 final message 末尾返回约定的结构化交接字段。
- 主 agent 默认用返回的交接字段汇总，不回读报告文件；仅在字段缺失或需要核对时回读 `report_path`。
- 中文输出；区分 事实 / 推断 / 假设；不得编造数据。

## Codex 并行模式约束

Codex 默认优先使用本文件的并行派发模板；若当前会话没有暴露 subagent 派发工具，或派发/等待过程失败，则直接使用串行降级模式。

Codex 派发时，每个 subagent prompt 必须自包含，至少包含：

- repo root：`{repo_root}`
- 对应步骤 skill 的 `SKILL.md` 与 `references/methodology.md` 路径
- 当前工作单元的完整输入上下文
- 输出文件路径规则与"已存在则追加 (1)(2)"要求
- final message 结构化交接字段要求

主 agent 收齐 final message 交接字段后汇总；字段缺失时才回读 `report_path`。已完成的 Codex subagent 应及时关闭或释放，避免占用并发资源。

## Step 2 派发模板（每个错位环节一个 subagent）

输入占位符：`{主题}`、`{环节名称}`、`{环节在全景中的位置}`、`{错位强度评分}`、`{利润增速落点}`、`{错位预计收窄时点}`、`{需求证据摘要}`、`{供给证据摘要}`、`{供给约束实证清单}`、`{Step1报告路径}`。

```text
你是 chain-alpha 工作流第二步的执行单元。只处理一个错位环节，不要扩展到其他环节。

主题：{主题}
目标环节：{环节名称}（在产业链全景中的位置：{环节在全景中的位置}）
第一步结论：错位强度评分 {错位强度评分}；利润增速落点={利润增速落点}；错位预计收窄时点={错位预计收窄时点}；需求证据={需求证据摘要}；供给证据={供给证据摘要}；供给约束实证={供给约束实证清单}。第一步报告：{Step1报告路径}。

任务：
1. 读取 invest-flow:chain-alpha-monopoly-screen 的 SKILL.md 与 references/methodology.md，严格按其规则执行。
2. 拆该环节上中下游子环节；列全球公司格局（必须含中国大陆及日韩台欧）。
3. 先执行硬门槛（CR3>50% 或寡头证据；毛利<25% 且无壁垒剔除；占比<20% 初筛剔除；利润增速<20% 剔除），再按 30 分候选评分排序，取前 ≤10 家。
4. 把报告写到 output/chain-alpha-monopoly-screen/chain-alpha-monopoly-screen-{环节名称}-{YYYY-MM-DD}.md（已存在则追加 (1)(2)）。

在 final message 末尾输出如下结构化交接（每家候选一行），不要省略字段：
report_path: <报告路径>
candidates:
- 公司 | Ticker | 子环节 | 候选30分 | 占比初值(置信度) | 利润增速(置信度) | CR3证据等级 | 上市地与可投性（可投主板，注明市场如 A股/港股/日股/台股/美股；仅粉单；未上市） | 待核实事项
若该环节 0 家通过硬门槛：注明"格局分散，暂不可投"并列格局最好的公司作背景。
```

## Step 2 → Step 3 主 agent 收口

主 agent 收齐各环节候选后，跨市场按候选 30 分排序，只挑可投主板候选 **top-K（默认 6）** 进入 Step 3 fan-out，不对全量候选逐一派发。单波并行默认 ≤6 个 subagent，超出分批。

## Step 3 派发模板（每家入选公司一个 subagent）

输入占位符：`{主题}`、`{环节名称}`、`{公司}`、`{Ticker}`、`{上市地与可投性}`、`{子环节}`、`{候选30分}`、`{占比初值与置信度}`、`{利润增速与置信度}`、`{CR3证据等级}`、`{待核实事项}`、`{Step2报告路径}`。

```text
你是 chain-alpha 工作流第三步的执行单元。只验证一家公司，不要扩展到其他公司。

主题：{主题}；所属环节：{环节名称}；公司：{公司}（{Ticker}）；上市地与可投性：{上市地与可投性}；子环节：{子环节}。
第二步结论：候选 30 分={候选30分}；占比初值={占比初值与置信度}；利润增速={利润增速与置信度}；CR3 证据等级={CR3证据等级}；待核实事项={待核实事项}。第二步报告：{Step2报告路径}。

任务：
1. 读取 invest-flow:chain-alpha-verification 的 SKILL.md 与 references/methodology.md，严格按其规则执行；按候选公司上市地使用同市场可比估值口径。
2. 先执行占比双轨硬门槛（≥40% 纯正 / 20-40% 增量贡献测试 / <20% 剔除）和利润增速硬门槛（<20% 剔除 / 20-30% 低档通过 / ≥30% 优先），再按 100 分模型评分并定四档（金池子≥80 / 通过65-79 / 待验证50-64 / 剔除<50），含负分项。
3. 本步只验证分级，不推断回撤、不算仓位（仓位由 Step 4 company-valuation-risk 统一给出）；弹性标的（占比 20-40%）必须显式标注。
4. 把验证卡写到 output/chain-alpha-verification/chain-alpha-verification-{Ticker}-{YYYY-MM-DD}.md（已存在则追加 (1)(2)）。

在 final message 末尾输出如下结构化交接，不要省略字段：
report_path: <报告路径>
档位: <金池子/通过/待验证/剔除>
总分: <N>/100（含负分 <-N>）
弹性标的: <是/否>（占比 20-40% 为是）
利润增速结论: <利润增速口径、区间、可持续性>
未来利润增速 g: <N>%（证据等级：指引/订单 / 一致预期 / 推断）
增速久期 N: <2/3/5> 年（依据：错位持续窗口 / 格局延续性 / 在手订单、产能锁定）
未来收入增速: <N>%（PS 轨与增速消化核对备用）
公司类型初判: <成长/现金牛/收费站/周期/脉冲/资产困境 + 一句话依据>（供 Step 4 类型闸门参考）
反证条件: <要点>
跟踪指标: <要点>
若数据不足无法定档：返回"验证未完成"并说明缺什么数据，不要编造档位。
```

## Step 3 → Step 4 主 agent 收口

主 agent 收齐验证卡后，只把档位为 `金池子 / 通过` 的标的送入 Step 4 fan-out（通常 2-3 家）；`待验证 / 剔除` 不派发，进观察池由 delivery-tracking 跟踪。

## Step 4 派发模板（每家通过及以上公司一个 subagent）

输入占位符：`{主题}`、`{环节名称}`、`{公司}`、`{Ticker}`、`{上市地}`、`{档位}`、`{弹性标的}`、`{公司类型初判}`、`{利润增速结论}`、`{未来利润增速g}`、`{增速久期N}`、`{未来收入增速}`、`{Step3报告路径}`。

```text
你是 chain-alpha 工作流第四步的执行单元。只处理一家公司的估值分位与建仓计划，不要扩展到其他公司。

主题：{主题}；所属环节：{环节名称}；公司：{公司}（{Ticker}）；上市地：{上市地}。
第三步结论：档位={档位}；弹性标的={弹性标的}；公司类型初判={公司类型初判}；利润增速结论={利润增速结论}；未来利润增速 g={未来利润增速g}；增速久期 N={增速久期N}；未来收入增速={未来收入增速}。第三步报告：{Step3报告路径}。

任务：
1. 读取 invest-flow:company-valuation-risk 的 SKILL.md 与 references/methodology.md，严格按其规则执行（类型闸门 → PE/PS 选尺+警戒线 → 5 年 TTM 分位带 → 潜在风险两腿取大 → 增速消化核对 → 建仓计划）。
2. 复核公司类型（第三步初判仅作参考）；排除类型（周期/脉冲/资产困境）→ 生成"不适用"报告，标的档位保留、不给分位法仓位。
3. 用 generate_report.py 生成报告，带入 --grade {档位}{弹性标的为"是"时加 --elastic}；仓位上限 = 回撤预算 ÷ 潜在风险，报告按 2%/5%/10%/20%/30%/50%/70% 逐档列表（--drawdown-budget 选主档，默认 2%），档位/弹性/数据不足折扣叠乘，警戒线触发新仓归零。
4. 做增速消化核对并填入报告第六节：合理 TTM PE = 退出倍数×(1+g)^(N+1)÷(1+r)^N（默认 r=10%、退出倍数 15），溢价 k = 当前值÷合理值，消化时间 t = ln(k)÷ln(1+r)（约束 t≤N），三态判定 + (g,N) 邻域小表；g/N 用第三步交接字段并保留证据等级。
5. 报告写到 output/company-valuation-risk/company-valuation-risk-{Ticker}-{YYYY-MM-DD}.md（已存在则追加 (1)(2)）。

在 final message 末尾输出如下结构化交接，不要省略字段：
report_path: <报告路径>
类型闸门: <通过（成长/现金牛/收费站）/ 不适用（周期/脉冲/资产困境）>
估值尺子: <TTM PE / TTM PS>
当前分位: <N>%（<定位区间>）
潜在风险: <-N>%（<50% 分位腿 / 参考点腿>）或 不可用
增速消化: <合理/低估 / 可消化 / 部分消化 / 透支>（g=<N>%（证据等级）, N=<年>, 溢价 k=<x.xx>, 消化时间 <t> 年）
行业×公司特别提示: <一句话定性判断（行业景气 × 公司地位；不影响公式与结论）>
警戒线: <未触发 / 触发（读数降置信度，新仓归零）>
仓位上限: <N>% 或 0%（警戒线）或 不适用
反证/复评条件: <要点>
若数据不足无法完成分位带：返回"定仓未完成"并说明缺什么数据，不要编造分位或仓位。
```

## 串行降级模式

若当前 agent 会话工具不可用或派发失败，主 agent 不使用本文件的派发动作，改为在当前会话内对每个环节/公司顺序套用上述同样的任务说明与交接字段，产出格式完全一致。
