# AI 基建板块发现方法论

## 目标

本方法论用于每周发现和排序 AI 基建板块。输出结果不是投资建议，而是决定哪些板块应该交给 chain-alpha 工作流（`chain-alpha-mismatch-discovery` / `chain-alpha-pipeline`）深挖。

## 评分模型

每个板块计算 `discovery_score`，满分 100，风险最高扣 10 分。

| 模块 | 权重 | 高分标准 |
|------|------|----------|
| 架构变化强度 | 15 | 明确由 GB300/Rubin、ASIC、MoE、CPO、液冷、高密度供电、长上下文或推理扩散等架构变化驱动 |
| 需求动量 | 20 | hyperscaler capex、订单、backlog、收入 YoY/QoQ、出货、装机或路线图持续上行 |
| 单位用量弹性 | 15 | 每 GPU、每 rack、每 MW、每 token、每训练集群的用量明显上升，最好能量化倍数 |
| 供给约束 | 20 | lead time、良率、扩产周期、认证周期、关键材料/设备/产能限制明确 |
| 财务兑现 | 15 | 代表公司收入、organic growth、毛利率、订单、指引或 estimate revision 已经改善 |
| 预期差 | 15 | 市场尚未充分定价，或财务兑现速度高于估值/叙事反应 |
| 风险扣分 | -10 | 扩产过剩、库存上升、ASP 下行、客户砍单、技术替代、监管或地缘风险 |

## 指标采集清单

每个板块至少尝试采集以下指标；缺失时写 `数据暂缺`。

| 指标 | 说明 | 典型阈值 |
|------|------|----------|
| 架构触发 | 由哪条 AI 架构变化驱动 | 必须明确到平台、产品路线图或系统变化 |
| 代表公司收入增速 | 板块代表公司相关业务 YoY/QoQ | YoY > 20% 或 QoQ 连续改善 |
| organic growth | 剔除并购后的真实增长 | > 20% 为强信号 |
| backlog / bookings | 订单可见度 | backlog YoY > 30% 或 book-to-bill > 1.2 |
| lead time | 供给紧张度 | > 20 weeks 为强信号，或较上季拉长 |
| ASP / price | 定价能力 | ASP 上升或跌幅小于行业均值 |
| utilization / capacity | 产能与利用率 | 利用率 > 85% 或扩产仍供不应求 |
| gross margin | 利润兑现 | 毛利率同比或环比改善 |
| capex / capacity plan | 需求和供给双方扩张 | 客户 capex 上修或供应商扩产 |
| estimate revision | 市场预期变化 | revenue/EPS consensus 上修 |
| relative performance | 市场定价 | 相对指数和同业表现 |
| valuation percentile | 估值拥挤度 | 估值分位低于同类高景气板块更有预期差 |
| evidence freshness | 数据新鲜度 | 优先使用 90 天内数据 |

## 分数口径

- `0`：无数据或证据反向。
- `1-2`：弱证据，主要是逻辑推演或单一来源。
- `3`：有可验证事实，但缺少量化或持续性。
- `4`：多个指标支持，且来源质量较高。
- `5`：多个高质量来源一致，指标超过阈值且趋势持续。

将每个模块折算到对应权重，不得因为主题热门而额外加分。核心数据缺失时，该模块最高只能给 60% 权重，并必须标记 `数据暂缺`。

## 动态新增规则

满足任一条件即可新增动态候选板块：
- 新平台或架构发布导致 BOM、功耗、互联、存储、封装或运维瓶颈变化。
- 至少两家代表公司在最近财报中对同一需求链条给出订单、收入或指引上修。
- 出现可验证的 lead time、价格、产能、良率或客户认证异常。
- 新 reference design、OCP 项目、客户标准或监管政策改变供应链位置。

动态新增板块必须说明：
- 来源事件。
- 触发日期。
- 与固定种子板块的关系。
- 是否需要下周继续保留。

## Chain-alpha handoff 规则

将板块交给 chain-alpha 工作流（轻量确认用 `chain-alpha-mismatch-discovery`，完整漏斗用 `chain-alpha-pipeline`）的条件：
- `discovery_score >= 80`：必须进入 handoff queue。
- `70 <= discovery_score < 80`：证据置信度为中或高时进入 handoff queue。
- `<70`：不进入 handoff queue，除非出现强订单、价格、交期或财报异常。

handoff 项必须包含：
- 后续命令。
- 触发阈值。
- 核心证据。
- 需要 chain-alpha 验证的关键问题（错位是否真实、供给为何扩不快、利润增速能否落地）。

## 输出解释

分类：
- 优先深挖：`discovery_score >= 80`。
- Chain-alpha 队列：`70-79` 且证据置信度中高。
- 观察池：`55-69`。
- 暂不深挖：`<55`。

变化方向：
- 上升：分数较上周上升，或关键指标改善。
- 持平：关键指标无明显变化。
- 下降：订单、价格、capex、财务或预期差恶化。
- 新增：本周首次进入候选池。

证据置信度：
- 高：公司文件、财报、交易所公告、客户披露、可验证行业数据一致。
- 中：有公司口径和第三方数据，但缺少直接量化或时间序列。
- 低：主要依赖二手报道、行业传闻或逻辑推演。
