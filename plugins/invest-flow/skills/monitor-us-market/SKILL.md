# 每日美股扫描

## Web Research Routing

- 当任务需要联网搜索、网页抓取或多页研究，且当前 agent 会话已安装对应 Firecrawl skill 时，优先使用 `firecrawl-search`（发现来源）、`firecrawl-scrape`（单页提取）、`firecrawl-crawl`（站点遍历）或 `firecrawl-deep-research`（多来源深研）。
- Firecrawl skill 不可用或调用失败时，再回退到当前会话提供的 web search / browser 工具。
- 工具优先级不得降低证据标准：仍优先公司公告、监管文件、交易所、IR 等一手来源，并按本 skill 的规则交叉验证。

## Overview

生成中文《美股收盘日报》，覆盖最近一个已完成的美股交易日。报告目标是帮助用户复盘昨夜美股发生了什么、为什么涨跌、资金流向哪里、哪些板块和个股异动，以及次日需要观察的风险和机会。

报告形态：结论前置（第 0 节是完整结论卡）、篇幅有硬预算（全文含表格 ≤300 行）、板块与主题按当日实际异动动态呈现（固定清单只作扫描宇宙，不逐项填表）。

输出目录：`./output/monitor-us-market/`

## 运行频率与事件触发

- **固定频率**：每个已完成的美股交易日结束后执行一次；报告日期始终取最近一个完整交易日。
- **补充触发**：常规收盘后若发生会显著改变大盘、板块或重点标的判断的重大盘后事件，应在信息可核验后补充更新，不等待下一次常规扫描。
- 补充更新必须标明原报告日期、事件发生时间和新增结论，避免把盘后信息混入尚未完成的交易时段。

## Workflow

### 1) 确认报告日期
- 默认使用最近一个已完成的美股常规交易日作为报告日期，标题格式为 `美股收盘日报｜YYYY-MM-DD`。
- 如果北京时间早上 8:00 对应的美股交易日尚未完整收盘，说明原因并使用最近一个完整交易日。
- 如果遇到美国市场休市，明确写出休市原因，并改为假期版市场观察。

### 2) 生成报告骨架
- 建议先运行：
  - `python plugins/invest-flow/skills/monitor-us-market/scripts/create_report.py --date YYYY-MM-DD`
- 脚本会读取 `references/report-template.md`，生成不覆盖旧文件的 Markdown 骨架。
- 生成后必须补齐真实数据和来源，不要把占位符作为最终报告交付。

### 3) 收集数据并做动态扫描
- 必须使用最新可验证数据；涉及当日行情、宏观、财报、新闻、FedWatch、利率和资金流时必须联网核验。
- 优先读取 `references/source-guide.md`，按权威程度和实时性选择来源。
- 必查核心：指数与宏观资产、七巨头、用户重点池（见 source-guide）。
- 动态扫描（板块与主题的呈现依据是当日数据，不是固定清单）：
  - 对 11 个 GICS 板块 ETF 和 source-guide 的主题 ETF 扫描宇宙按当日涨跌幅排序，取两端入表。
  - 用 Finviz Groups、Barchart ETF performance 等一页式来源提高扫描效率。
  - 主动找池外新动态线索：52 周新高/新低群体、量比异常、盘后重大事件、群体性板块异动。
- 可用本仓库 `market-data-router` 或 Yahoo Finance 辅助获取行情，但关键结论仍需交叉验证。

### 4) 处理冲突和缺失
- 如果不同来源数据冲突，写出差异，优先采用更权威或更实时的数据。
- 无法可靠获取的数据必须写 `暂无可靠数据`；整表拿不到时删除该表并在「数据缺口」节说明，不留空表格。
- 对盘后新闻、财报反应、机构观点和期权异动区分“已确认事实”和“市场解读”。

### 5) 按模板输出
- 报告 = 模板的 0-7 节加可选「数据缺口」节，顺序固定，不增删章节。
- 第 0 节是完整结论卡：一句话总结、市场阶段单选、操作倾向、最值得关注的 5 个信号、明日最大变数。正文写完后回头把第 0 节改到「只读这一节也能做决策」的程度。
- 全文（含表格）目标 150-250 行，硬上限 300 行。超限时先删：无异动个股行、拿不到数据的表、与第 0 节重复的判断句。
- 表格行遵守阈值报告制：池内个股 |涨跌幅| ≥2% 或有实质新闻/财报才入表；主题 ETF 只报扫描排序的 Top5/Bottom5；宽度指标拿不到的合并成一行说明。
- 使用中文；金融术语可保留英文，例如 RSI、MACD、P/E、FedWatch、RPO、ARR。
- 结论使用中性语言，不构成投资建议。

### 6) 交付前自检
- 第 0 节完整且可独立成文，5 个信号都含具体点位、数据或日期。
- 第 3 节新动态雷达已填：有新动态给 2-5 条，确无新动态写明「未发现」及扫描范围。
- 全文无占位符、无空表格行，总行数 ≤300。
- 任何一条不满足就修完再交付，不把骨架或半成品当最终报告。

## Quality Rules

- 不编造数据、新闻、财报数字、机构观点或来源链接。
- 每个关键事实、重要数据、公司新闻、宏观数据和财报数据都注明来源或链接。
- 明确区分：行情事实、新闻事实、推断、交易计划、风险提示。
- 第 0 节核心结论卡必须包含：当前市场阶段、操作倾向、最值得关注的 5 个信号；这是全报告最重要的一节。
- 板块与主题按当日实际涨跌排序呈现；source-guide 的清单是扫描宇宙和重点池定义，不是逐项填表清单。
- 第 3 节新动态雷达为必填结构：满足触发标准的池外主题性/群体性异动 2-5 条；确无新动态时如实写明并给出扫描范围，禁止硬凑。
- 用户重点池（大型科技、AI 硬件/半导体、软件/SaaS、光通信/AI 互连、AI 电力/数据中心基础设施)按阈值报告制覆盖：有异动的写透，无异动的一行带过。
