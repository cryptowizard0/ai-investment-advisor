# chain-alpha 供需错位环节发现

## Web Research Routing

- 当任务需要联网搜索、网页抓取或多页研究，且当前 agent 会话已安装对应 Firecrawl skill 时，优先使用 `firecrawl-search`（发现来源）、`firecrawl-scrape`（单页提取）、`firecrawl-crawl`（站点遍历）或 `firecrawl-deep-research`（多来源深研）。
- Firecrawl skill 不可用或调用失败时，再回退到当前会话提供的 web search / browser 工具。
- 工具优先级不得降低证据标准：仍优先公司公告、监管文件、交易所、IR 等一手来源，并按本 skill 的规则交叉验证。

## Overview

本 skill 是 chain-alpha 工作流的第一步，从一个大主题出发回答五个问题：行业是什么（先用白话讲清它是什么、替代什么、为什么现在需要，再落到细分行业、解决的问题、商业逻辑），增长快不快（收入/行业增速是否 >20%、处于哪个产业周期阶段、为什么快且为何能维持高位、能持续多久），这条产业链长什么样（全景），哪些环节存在供需错位（需求增量大、供给跟不上），哪些错位最终能落到利润增速。

核心原则：先行业定义和增长初筛，再全景，后错位。不允许跳过行业定义、增长判断或全景直接给错位结论。若行业增长门槛失败，流程在增长判断后终止，不进入产业链全景、错位环节识别或第二步；若增长门槛通过但最后没找到错位环节，行业定义、增长判断和全景列表本身也是有效产出。

第一性原理：股价长期跟着公司利润走，所有行业/环节筛选指标最终必须落到"利润增速"。行业/收入增速 >20% 只是增长初筛，利润增速最好 ≥30%，最低 ≥20%；代表公司或可投标的的可持续利润增速低于 20% 的环节不得进入第二步，只能进入观察池或标记为"高景气但利润弹性不足"。

默认输出目录：`./output/chain-alpha/`

## Trigger

- `使用 invest-flow:chain-alpha-mismatch 分析 AI 数据中心电力`
- `拆解 <主题> 的行业逻辑、增长情况、完整产业链并找供需错位环节`
- 作为 `chain-alpha` 的第一步被调用

输入必须是用户给定的大主题（如"AI 数据中心电力""机器人执行器""先进封装"）。本 skill 不做全市场自动扫描；用户未给主题时必须先要求用户提供。

## Workflow

### 1) 明确主题边界
- 提取主题、地区、时间窗口。
- 用户未指定时，默认全球视角（含中国大陆及日韩台欧），时间窗口 6-24 个月。

### 2) 收集证据
- 涉及需求量、产能、价格、交期、订单、财务、利润增速、扩产计划时，必须查最新公开来源。
- 优先使用公司财报、Investor Relations、earnings call、交易所公告、行业协会和权威数据。
- 区分 `事实 / 推断 / 假设`；关键数字标注来源和日期；不可得标注"不确定"或"数据暂缺"，不得编造。

### 3) 第一段：行业定义（不得跳过）
读取 `references/methodology.md`，先说明这个主题对应的细分行业是什么。

- **先讲人话**：在六字段表之前，必须先用面向非行业读者的白话回答四个问题——它是什么（一句话定义 + 白话展开）、它替代 / 对比什么现有方案、为什么现在需要它、它在整机 / 系统中的位置。禁止用行业黑话解释行业黑话；读者测试是"不懂该行业的人读完能向别人复述这个行业卖什么、替代什么、为什么现在火"。
- 固定字段：细分行业、解决的问题、商业逻辑、终端客户、预算来源、价值链赚钱方式。
- 若主题覆盖多个细分行业，先列出候选细分行业，再明确本次分析主边界。
- 行业定义必须区分 `事实 / 推断 / 假设`，不可把主题叙事直接等同于商业逻辑。

### 4) 第二段：增长判断（不得跳过）
判断行业或关键环节增长是否足够快，以及增长能持续多久。

- 行业 / 收入增速 >20% 是增长初筛硬门槛，不是进入第二步的充分条件。
- 必须回答：增速快不快、现在处于哪个产业周期阶段、为什么快、能持续多久。
- **产业周期定位**：在 技术验证期 / 商用起步期 / 规模上量期 / 大规模渗透期 四阶段中定位当前节点，输出各阶段预测时间表（每阶段绑定一个可验证里程碑），用 `← 当前节点` 标注；细则和示例见 `references/methodology.md`。
- 增长证据至少覆盖预算来源、渗透率 / 单位用量 / 替换周期 / capex / 政策 / 技术升级中的相关驱动。
- **增速为何能维持高位（门槛通过时必做）**：逐驱动给出可见性证据（订单 / backlog 覆盖、capex 指引年限、渗透率距天花板距离、单位用量路线图），指出最先衰减的驱动和增速下台阶的最早触发信号。
- **行业增长门槛（一票否决）**：必须同时具备有证据的行业 / 关键环节收入增速 >20%、增长原因清楚、可持续窗口至少 6 个月；任一项失败则标记"行业增长门槛失败"，输出行业定义 + 增长判断 + 触发条件后终止，不进入产业链全景、错位识别或 `chain-alpha-monopoly`。
- 可持续利润增速 ≥20% 仍是放行硬门槛，≥30% 优先；不得用收入增速替代利润增速。

### 5) 第三段：产业链全景（不得跳过）
读取 `references/methodology.md`，从终端需求倒推，把整个产业链按 上游 / 中游 / 下游 / 生态支撑 完整列出。

- 每个环节用列表呈现，固定字段：环节名称、作用、需求来源、供给弹性、代表公司、价值池大小、利润增速线索。
- 全景必须覆盖整条链，不允许只列感兴趣的部分。
- 全景列表是报告的独立章节。

### 6) 第四段：错位环节识别
在全景列表基础上逐环节做供需错位判断。每个候选错位环节必须回答并附证据：

- **需求为什么增加**：增量来源、预算来源、单位用量是否非线性。
- **供给为什么跟不上**：扩产周期 / 技术壁垒 / 公司不愿扩产（资本纪律）/ 认证周期，至少落实一项。
- **供给何时赶上来（供给响应时钟）**：扩产证据必须双向读——既证明当下供给跟不上，也标注已公告扩产的落地时点与"错位预计收窄时点"；给不出就标注"无可见供给响应"。
- **利润增速如何兑现**：错位是否能转化为代表公司或可投标的的净利润 / operating profit / EPS 增速；未来 1-2 年可持续利润增速 <20% 的环节不得进入第二步，20-30% 低档通过，≥30% 优先。

**硬门槛（一票否决）**：必须同时具备需求增量证据 + 供给约束实证（价格上涨、交期拉长、订单积压、产能利用率至少一项）+ 利润增速落点（可持续利润增速 ≥20%），否则只能标记"高景气，非错位"或"利润弹性不足"，不得进入第二步。

### 7) 错位强度评分
对通过硬门槛的环节按 0-5 逐项打分，满分 30：

| 维度 | 分值 |
|---|---|
| 需求增量确定性 | 0-5 |
| 单位用量弹性 | 0-5 |
| 供给约束强度 | 0-5 |
| 证据强度（实证数量与质量） | 0-5 |
| 错位定价程度（反向：越未被定价分越高） | 0-5 |
| 利润增速兑现度（利润增速与可持续性） | 0-5 |

得分最高的 2-4 个环节进入第二步（`chain-alpha-monopoly`），其余进入观察池。

### 8) 输出报告
- 使用 `references/report-template.md` 输出中文 Markdown 报告。
- 保存至 `./output/chain-alpha/chain-alpha-mismatch-{主题}-{YYYY-MM-DD}.md`。
- 文件已存在时追加 `(1)`, `(2)`，不覆盖。
- 报告必须包含固定作者字段：`InvestmentFlow`。

## Quality Rules

- 中文输出；金融、技术术语可保留 English。
- 不允许跳过行业定义、增长判断或产业链全景直接给错位结论。
- 行业定义必须先有白话解释并通过读者测试（非行业读者能复述这个行业卖什么、替代什么、为什么现在火），不得用行业黑话解释行业黑话。
- 增长判断必须包含产业周期时间表（四阶段 + 预测时间 + 当前节点标注）；门槛通过时必须逐驱动解释增速为何能维持高位。
- 收入增速 >20% 是进入产业链全景和错位识别的增长初筛硬门槛，但不能替代供需错位实证或利润增速硬门槛。
- 行业增长门槛失败时必须终止，不得为了完成工作流强行进入后续环节。
- 全景列表必须覆盖整条链，每个环节字段齐全。
- 不允许把"大需求"直接等同于"错位"；没有供给约束实证只能标"高景气，非错位"。
- 不允许把"收入增长"直接等同于"利润增速"；利润增速低于 20% 的环节不得进入第二步，20-30% 低档通过，≥30% 优先。
- 公司格局必须含中国大陆及日韩台欧供应商。
- 每个错位环节必须标注其在全景列表中的位置。
- 扩产证据必须双向读；供给响应时钟为错位环节卡片必填字段，已公告产能落地 ≤12 个月且足以覆盖缺口的环节须标注"错位收窄中"。
- 错位定价程度评分必须落在证据上（代表公司近 12 个月涨幅、估值自身历史分位、卖方一致预期至少一项），不得凭印象打分；0-1 分（充分定价）的环节进入第二步时必须在交接中显式标注"定价拥挤"。
